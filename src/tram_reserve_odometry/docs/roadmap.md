# Ограничения решения и план развития

## Ограничения

- **Нужна начальная выставка по GNSS.** 
- **Один маршрут.** Карта (`maps/`) построена для кольца Таллинская ↔ Щукинская;
  новый маршрут требует новой карты и списка остановок.
- **Один тип вагона.** Характеристика привода `f(u, v)` идентифицирована для 71-911ЕМ
  по датасету; коэффициенты сопротивления выведены из его паспорта.
- **Продольная ошибка между привязками растёт** с пройденным путём (масштаб колёс,
  проскальзывания); её снимают только остановки из `maps/stops.yaml` и GNSS-фиксы.
- **Износ колёс не оценивается** явно: отличие масштаба колеса вагона накапливается в
  ошибке пути.
- **Ветки** (тупики у Таллинской) описаны грубо, и очень тяжело распознавать куда именно трамвай поехал на самом деле.
- **Точность проверена на одном проверочном bag** с эталоном судьи.

## План развития

1. **Оценка масштаба колеса** в фильтре (состояние `ε`) по привязкам к остановкам и
   GNSS — убрать систематическую часть продольного дрейфа.
2. **Проверка на большем числе прогонов** с эталоном судьи и нагрузочные замеры на
   бортовом вычислителе.
3. **Карта веток** по GT и включение перепривязки к веткам по GNSS.
4. **Идентификация привода по вагонам**: отдельная `f(u, v)` или поправка для каждого
   вагона, онлайн-уточнение характеристики.
5. **Детектор проскальзывания как отдельный плагин** с асимметрией тяга/торможение по
   физике сцепления и условиям рельса.
6. **Смешивание режимов: мат. модель и IMU**: IMU можно использовать для распознавания того, на какую именно ветку кольца заехал трамвай. Либо на какое из нескольких ответвлений он повернул.
