# Точность и быстродействие

## Методика

Проверка идёт через **чекер организаторов** (`hackathon_solution_checker`) на
тестовом bag `30618_88aea4d9`, в контейнере организаторов (`ros:humble-ros-base`):

```bash
colcon build && source install/setup.bash
ros2 launch tram_reserve_odometry reserve_odometry.launch.py bag:=bags/30618_88aea4d9
```

1. запускаются нода (конфиг `configs/*.yaml`) и чекер;
2. bag проигрывается в реальном времени (1x);
3. чекер сопоставляет `/result/velocity` и `/result/position` с эталоном
   `/localization/kinematic_state` по `header.stamp` (допуск 0.05 с) и считает RMSE и
   максимум ошибки скорости и положения — покомпонентно (x, y, z) и по 3D-расстоянию;
4. дополнительно: частота выходов (`ros2 topic hz`, запись `ros2 bag record`), задержка
   «приём входа → публикация» (`latency_ms` в `/diagnostics`, steady clock) и CPU/RSS
   процесса ноды (`/proc`, раз в секунду).

## Результаты

### Регулярный маршрут (основной сценарий)

По уточнению организаторов, на проверке трамвай будет ездить преимущественно по
регулярному маршруту. В последние ~2 минуты тестового bag трамвай съезжает с маршрута
в депо — это не регулярный маршрут (и его нет на карте), поэтому основная оценка — на
bag без последних 2 минут.

| Величина | RMSE | max | n |
|---|---|---|---|
| скорость, м/с | 0.026 | 0.311 | 23 791 |
| x, м | 0.488 | 1.539 | 23 783 |
| y, м | 0.339 | 1.897 | 23 783 |
| z, м | 0.153 | 0.699 | 23 783 |
| 3D-расстояние, м | 0.614 | 1.909 | 23 783 |

Частота выходов: `/result/velocity` и `/result/position` — 20 Гц (требование ≥ 10 Гц).

### Полный bag (со съездом в депо)

| Величина | RMSE | max | n |
|---|---|---|---|
| скорость, м/с | 0.029 | 0.316 | 26 190 |
| x, м | 4.009 | 33.588 | 26 183 |
| y, м | 4.258 | 37.504 | 26 183 |
| z, м | 0.209 | 1.364 | 26 183 |
| 3D-расстояние, м | 5.852 | 50.288 | 26 183 |

Последние ~2 минуты почти не меняют ошибку скорости
(RMSE 0.026 → 0.029 м/с), но поднимают 3D RMSE положения с 0.61 до 5.85 м:
пути в депо нет на 1D-карте, и положение на этом участке с реальной траекторией не
совпадает.

## Быстродействие (первые 60 с bag)

| Величина | Значение |
|---|---|
| задержка «приём входа → публикация», среднее / p50 / p95 | 4.4 / 2.9 / 3.6 мс |
| CPU ноды, среднее / max | 1.0 / 2.0 % одного ядра |
| память ноды (RSS), max | 25.3 МБ |

Цикл публикации — таймер 20 Гц, поэтому задержка включает ожидание такта (0–50 мс) и
зависит от фазы таймера относительно входов: в разных запусках среднее 4–16 мс.
Требование — ≤ 100 мс.

Офлайн-прогон той же ноды по bag (`reserve_odometry_replay`, без реального времени)
обрабатывает этот bag (46 744 сообщения) за ~0.6 с.

## Ограничения оценки

- Проверка на одном bag: эталон судьи (`/localization/kinematic_state`) есть только в
  проверочном bag организаторов, в bag датасета его нет.
- Карта маршрута и характеристика привода построены по GNSS и тележкам датасета, поэтому
  на новых данных точность может быть ниже.
- Съезда в депо нет на карте, поэтому этот участок оценивается отдельно (полный bag).
