# Архитектура

Пакет `tram_reserve_odometry` — это **тонкая ROS-нода**. Она связывает компоненты в один цикл по таймеру; компоненты, через которые проходят данные из подписок, потокобезопасны. Алгоритмы вынесены в **сменные плагины** (pluginlib). Геодезия и карта от ROS не зависят.

## Слои

```
┌──────────────────────────────────────────────────────────────────┐
│  ROS-слой: ReserveOdometryNode                                   │
│  параметры, таймер, GNSS-выставка, выбор точки и системы вывода  │
├──────────────────────────────────────────────────────────────────┤
│  IO: InputBridge (подписки)  │  OutputBridge (публикации)        │
├──────────────────────────────────────────────────────────────────┤
│  Предобработка (плагин IPreprocessor, без ROS)                   │
├──────────────────────────────────────────────────────────────────┤
│  Оценка (без ROS): EstimationPipeline                            │
│  traction → slip → estimator → integrator (StopResetRoute)       │
├──────────────────────────────────────────────────────────────────┤
│  Карта (без ROS): RouteMap — кольцо + ветки, s → (x, y, z, курс) │
├──────────────────────────────────────────────────────────────────┤
│  Ядро (без ROS, header-only): types, interfaces, plugin_registry,│
│  geo (ENU ↔ WGS84 ↔ UTM/MGRS, OutputProjector)                   │
└──────────────────────────────────────────────────────────────────┘
```

## Один цикл (по стенному таймеру, `output_rate_hz` = 20 Гц)

1. **InputBridge.** Три подписки. Каждый образец получает свой `header.stamp` (время bag) и время приёма по steady clock (для задержки) и кладётся в `RawInputBuffer` под mutex.
2. **Выставка по GNSS.** Работает, пока не завершилась; время — по меткам bag. Подробности ниже.
3. **Preprocessor** (плагин). Приводит единицы: км/ч → м/с, ручка → [−1, 1]. Опорное время — самая свежая метка входов, возраст каналов считается в мс.
   `PassthroughPreprocessor` данные не трогает: отбраковка выбросов и отказов тележек — в оценщике.
4. **EstimationPipeline.** Цепочка: модель тяги → детектор проскальзывания → оценщик скорости → интегратор. При невалидном входе держится последняя оценка. Шаг интегрирования `dt` — разность меток входов.
5. **to_output.**
   - Выбор точки: `output.point` — `base_link` или точка пути под антенной master (`s + direction·x_master`).
   - Перевод ENU → `output.frame` (`mgrs` / `enu` / `relative`) через `geo::OutputProjector`, с учётом сближения меридианов для курса.
   - Без привязки к карте позиция остаётся относительной, в лог пишется предупреждение.
6. **OutputBridge.**
   - Публикуется `/result/velocity`.
   - `/result/position` — только когда позиция определена: карта выключена или выставка завершена.
   - `/debug/*` и `/diagnostics` (с `latency_ms`).
    - Повторная публикация той же метки времени пропускается.

## Таймлайн и часы

Порядок ступеней — в разделе «Один цикл». Ключевой момент: модули стоят на разных
ступеньках конвейера **и живут в разных шкалах времени** — таймер (20 Гц) задаёт только
такт публикации, а каждый модуль ведёт своё время.

```
tick 20 Гц
├─ InputBridge: из буфера последние образцы (front/rear 10 Гц, driver 20 Гц)
├─ выставка по GNSS (только пока не привязались; время bag)
├─ Preprocessor: км/ч→м/с, stamp = самая свежая метка входов
├─ Traction (плагин): f(u,v) − w0 — на метке публикации
├─ Slip detector
├─ Estimator: predict до меток тележек → update → predict до метки публикации
├─ Integrator: u += (1+ε)·v·dt, dt = Δ меток публикации
├─ to_output: точка (base_link/master) + ENU → MGRS
└─ OutputBridge: /result/*, /debug/*, /diagnostics
```

| Модуль | Шкала времени | Что видит |
|---|---|---|
| InputBridge | метка образца (bag) + приём (steady clock) | каждый канал отдельно |
| Выставка по GNSS | время bag, первые ~10 с | фиксы двух антенн |
| Preprocessor | самая свежая метка входов | последние образцы всех каналов |
| Traction (плагин) | метка публикации | последняя ручка + среднее тележек |
| Estimator | метки тележек + экстраполяция до публикации | только новые образцы (stamp > прошлый) |
| Integrator | цикл публикации (dt = Δ stamp, 20 Гц) | v от оценщика + dt |
| to_output / OutputBridge | метка публикации / now | оценка |

Следствия:

- **Оценщик «ходит во времени» внутри.** У него собственное время состояния `t_ns_`,
  которое движется по меткам измерений: predict → update → (при outage) predict →
  predict до метки публикации. Один вызов `estimate()` может пройти несколько таких
  циклов, если за такт пришло несколько меток тележек.
- **Тяга применяется в два момента.** `compute_acceleration()` на ступени пайплайна
  (метка публикации) в режиме модели игнорируется; настоящая тяга считается внутри
  оценщика на подшагах прогноза, с ручкой, **запоздалой на τ** (история `u_hist_`).
- **Интегратор интегрирует по циклам публикации, а не по тележкам.** Его dt — разность
  меток ручки (20 Гц), а не 10 Гц тележек; скорость он берёт уже экстраполированную
  оценщиком к метке публикации.
- **Модули нельзя переставить.** Порядок и шкалы времени жёстко связаны: интегратор
  использует `(route, s)` прошлого цикла, а оценщик — уклон `i(s)` с карты для модели
  следующего (cycle coupling через `set_route_context`).

## Модули ↔ матмодели

Математическая модель решения делится на две половины, связанные скаляром скорости и картой.

**Матмодель трамвая** (скорость и перемещение) — всё в `plugins/`, без ROS:

| Модуль | Что делает |
|---|---|
| `KalmanWheelEstimator` | фильтр скорости `[v, a, θ_T, θ_B, b]`: режим «модель привода» (τ, T, уклон, кривые, аэродинамика, адаптивные θ) с fallback на кинематику Зингера, робастные правила, ZUPT, прогноз к метке публикации |
| `TableTractionModel` | табличная характеристика тяги `f(u, v)` из `maps/drive_map.csv`, выше края таблицы — постоянная мощность |
| `StopResetRouteIntegrator` | `RouteIntegrator` (путь по 1D-карте) + сброс продольной ошибки `s` на стоянках у остановок из `maps/stops.yaml` |

**Матмодель пути** (карта) — `map/`, `core/`, `maps/`:

| Модуль | Что делает |
|---|---|
| `RouteMap` | 1D-карта (кольцо + ветки): `s → (x, y, z, heading, уклон, кривизна)`, проекция точки на путь |
| `core/geo.hpp` | геодезия без внешних зависимостей: ENU ↔ WGS84 ↔ UTM/MGRS, `OutputProjector` |
| `maps/` | данные: кольцо, ветки, остановки, таблица тяги |

**Мосты между половинами:**

- **Выставка по GNSS** (в ноде, `src/node/reserve_odometry_node.cpp`) — ставит трамвай
  (base_link из двух антенн) на путь: компас → проекция на карту.
- **`StopResetRouteIntegrator`** — гибрид: фильтр положения (трамвай) наследует
  `RouteIntegrator` (путь) и работает с картой и с остановками `maps/stops.yaml`.

**Почему фильтры не слиты в один:**

- разные шкалы времени (см. «Таймлайн и часы»): оценщик событийный (метки тележек),
  интегратор циклический (20 Гц);
- связь — через скаляр скорости `v` и через карту (уклон `i(s)`), а не через общее
  состояние;
- интерфейсы плагинов независимы: оценщик и интегратор заменяются по отдельности
  (см. [`plugins.md`](plugins.md)).

## Выставка по GNSS и карта

Используется только при `map.enabled`.

- Нода подписана на `/sensing/gnss/<position_antenna>/fix` и `/sensing/gnss/<orientation_antenna>/fix`.
- **Компас.** Два фикса с разницей меток ≤ `gnss_match_tolerance_s` дают ось трамвая `u`. Положение base_link = антенна − x_антенны·`u`. base_link проецируется на все маршруты карты (`RouteMap::project_global`), получаются `route_id`, `s0` и направление `direction`.
- **Запасной вариант.** Ось берётся из смещения антенны за `init_window_s`.
- **Таймаут.** Если за `init_timeout_s` по времени bag выставиться не удалось, нода переходит в относительный режим.
- **После выставки** GNSS-подписки закрываются: GNSS в контуре больше не используется.
  Исключение — `map.gnss_correction` (включено в конфиге): подписки остаются, и
  RTK-фикс(ы) — пара master + rover или одиночная антенна, по `gnss_corr_require_pair` —
  с проверками согласованности телепортируют s интегратора
  (`IPositionIntegrator::correct_s`). Сброс по остановкам
  (`StopResetRouteIntegrator`) — мягкий (`K = σ²/(σ² + σ_ост²)`) или телепорт
  (`integrator.stop_teleport`).
- **RouteIntegrator** (база `StopResetRouteIntegrator`) ведёт маршрут `route_id` и `s`. На кольце `s` берётся по модулю L. Если трамвай проезжает конец ветки (s > длины ветки), интегратор переходит на кольцо в точке `join_s_ring`, сохраняя физическое направление. При `dt = 0` позиция всё равно пишется (без продвижения по `s`).
- **StopResetRouteIntegrator** (по умолчанию с картой) — то же плюс сброс продольной ошибки `s` на стоянках у остановок из `maps/stops.yaml`. Окно поиска остановки — по накопленной с последней привязки неопределённости пути; нода передаёт ошибку выставки (поперечное отклонение base_link от пути). Подробно — [`plugins.md`](plugins.md).
- **RouteMap.** Шаг и длина кольца берутся из колонки `s_m`. `z` — высота рельса из `alt_m`; у веток — высота кольца в точке слияния.

Системы координат описаны в [`coordinates.md`](coordinates.md).

## Ключевые решения

- **Время — из bag.** Все метки берутся из `header.stamp` входов. Таймер публикации работает по стенным часам, поэтому `use_sim_time` и `--clock` не нужны. Задержка измеряется по steady clock от приёма входа до публикации.
- **Единицы приводятся в одном месте** — в предобработке. Выход — в м/с.
- **Внутри ENU, наружу MGRS.** Карта и интегрирование ведутся в ENU; перевод в систему судьи делается только при публикации.
- **Деградация, а не сбой.** Потерю или устаревание входов, отсутствие GNSS и отказ выставки нода переживает: держит оценку и сообщает о проблеме в `/diagnostics` и в лог.

## Потоки

Подписчики пишут в `RawInputBuffer` под mutex. Таймер и подписки GNSS выполняются однопоточным executor-ом, поэтому состояние предобработки, пайплайна и выставки синхронизации не требует.
