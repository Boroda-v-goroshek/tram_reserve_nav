# Допущения, ограничения модели и конфигурируемые параметры

## Допущения

- Вагон — жёсткое тело на рельсах; продольное движение описывается одной координатой
  пути `s` вдоль 1D-карты. Боковой динамики и отрыва от пути нет.
- Обе тележки измеряют скорость одного кузова; расхождение — отказ датчика,
  проскальзывание или износ колеса, а не реальная разница скоростей.
- Сила на ободе зависит только от позиции ручки и скорости (`f(u, v)`); тяговый привод —
  с запаздыванием `τ` и инерцией первого порядка `T`.
- Загрузка (масса) неизвестна и меняется на остановках — оценивается как множитель
  `θ = m_ref/m` в паспортных границах.
- Эталон судьи — поза base_link (ось передней тележки на уровне головки рельса) в MGRS
  ([`coordinates.md`](coordinates.md)).
- Маршрут на проверке тот же, что в датасете (кольцо Таллинская ↔ Щукинская); GNSS есть
  хотя бы в первые секунды прогона.

## Ограничения модели

- Без GNSS в начале прогона нода не может привязаться к карте: скорость публикуется,
  положение — только относительное (от старта), не в MGRS.
- Масштаб колеса (износ бандажа, до −6.5 %) отдельно не оценивается: его систематическая
  часть накапливается в продольной ошибке и снимается сбросом на остановках и коррекцией
  по GNSS.
- Характеристика привода `f(u, v)` идентифицирована по 26 прогонам датасета для
  71-911ЕМ; для другого типа вагона нужна новая идентификация. При автоведении (ручка не
  отражает тягу) модель отключается монитором, фильтр работает по кинематике.
- Коэффициент уклона `k_g` = 0.779 — калибровочный: поглощает шум уклона карты,
  посчитанного по GNSS-высоте (по паспорту было бы ≈ 0.94).
- Геометрия тупиковых веток у Таллинской грубая (~3.5 м); перепривязка к ветке по GNSS
  выключена (`map.gnss_reloc: false`).
- Паспортные числа 71-911ЕМ взяты из выжимки, первоисточник не сверен; с данными
  сверены мощность, масса и сопротивление ([`physical_model.md`](physical_model.md), п. 4).
- **Ручка задаёт силу не всегда.** `f(u, v)` — статическая функция позиции ручки и скорости,
  а у контроллера есть режимы: долгое удержание позиции −8 работает как регулятор скорости
  (вагон идёт ~3 м/с при любом уклоне; в bag жюри на −8 он разгоняется с 2.4 до 4.7 м/с),
  встречается автоведение (ручка в нейтрали, вагон разгоняется; в датасете 78 эпизодов,
  медиана 4.5 с). Такие участки монитор переводит на кинематику — модель привода там не
  работает, и при одновременном отказе тележек ошибка растёт.
- **Трогание со стоянки.** После перевода ручки в тягу вагон трогается через ~1.2 с
  (p10–p90 1.09–1.31 с по датасету: отпуск тормоза), а модель — через ~0.5 с (`τ` + `T`
  одни для всех режимов). Существенно только при счислении без тележек.
- **Сопротивление и уклон — эффективные коэффициенты.** `f(u, v)` и `w₀` идентифицированы
  без аэродинамики и кривых; `c_aero`, `k_curve` добавлены поверх. `k_g` = 0.779 занижен
  шумом уклона карты (ослабление регрессии, [`physical_model.md`](physical_model.md), п. 3.3):
  на длинных уклонах сила тяжести недоучтена примерно на 17 %.
- **Масса** оценивается медленно (`θ` — случайное блуждание), а меняется скачком на остановках;
  опорная масса таблицы и границы `θ` — оценки.
- **Статус проскальзывания** считается по относительному расхождению тележек: разный износ
  бандажей (до 6.5 %) даёт постоянную разницу, которую статус примет за скольжение (LOW/MEDIUM).
- **Петли карты** у конечных построены по траектории антенны на кузове; на крутых кривых путь
  по карте не равен пути колёс. Продольная ошибка на петлях растёт в среднем на −0.6 % пути
  (до −2.9 % на отдельных участках 50 м) против −0.15…−0.2 % на прямых путях A/B; её снимает
  сброс на остановке у петли.
- **Привязка к остановке — одна гипотеза.** Невязка больше окна — сброса нет; при быстром
  росте ошибки привязка теряется до следующей GNSS-коррекции. 8 % стоянок дольше 3 с в
  датасете — в 3–20 м от остановки (очередь, светофор): возможен ложный сброс на эти метры.
- **GNSS-коррекция** — перенос положения в точку фикса с фиксированной `σ`, без модели шума
  фикса: согласованное ложное RTK-решение проходит проверки
- **Шумы фильтра** (`kf_r`, `kf_q_jerk`, `drv_q_*`) заданы по датасету, согласованность
  ковариаций (NIS) не проверялась; модель и кинематика переключаются жёстко (по порогу
  монитора), а не смешиваются с весами.

## Конфигурируемые параметры

Конфиг — `configs/*.yaml` пакета, каждый параметр определён ровно в одном файле, у
каждого — комментарий с единицами и смыслом. Ниже — основные.

### Начальное положение и вагон

| Параметр | Файл | Значение | Смысл |
|---|---|---|---|
| `initialization.initial_position` / `initial_velocity` | `initialization.yaml` | `[0,0,0]` / 0 | начальные условия до выставки по GNSS (после — с карты) |
| `map.enabled` | `map.yaml` | true | 1D-карта и выставка по GNSS |
| `map.init_window_s`, `map.init_timeout_s` | `map.yaml` | 2 / 10 с | окно выставки; без неё дольше таймаута — относительный режим |
| `map.reference` | `map.yaml` | 55.810367, 37.462267, 168 | опорная точка ENU карты |
| `vehicle.master_antenna_x`, `rover_antenna_x` | `vehicle.yaml` | −9.873 / 2.563 м | TF антенн в base_link |
| `output.frame`, `utm_zone`, `mgrs_origin`, `point` | `output.yaml` | mgrs, 37, (300000, 6100000), base_link | система и точка вывода |
| `input.bogie_velocity_unit`, `driver_cmd_max` | `input.yaml` | kmh, 15 | единицы тележек, нормировка ручки |

### Масса, сопротивление, привод (`drive.yaml`)

| Параметр | Значение | Смысл |
|---|---|---|
| `drv_theta_min` / `drv_theta_max` | 0.8 / 1.25 | границы множителя массы `m_ref/m`: тара 24.6 т … 150 пассажиров 35.1 т |
| `drv_sigma_theta0`, `drv_q_theta` | 0.15, 1e-3 | начальная неопределённость и шум множителей массы |
| `drv_w0` | 0.046 м/с² | основное сопротивление (≈ 5 Н/кН) |
| `drv_c_aero` | 1.3e-4 1/м | аэродинамика `c·v²` (ρ·c_x·A/(2·m_eq)) |
| `drv_k_curve`, `drv_r_min` | 4.0 м²/с², 18 м | сопротивление в кривых `k/R`, ограничение шума кривизны |
| `drv_kg` | 0.779 | коэффициент уклона |
| `drv_tau`, `drv_T` | 0.225 с, 0.1375 с | запаздывание и инерция привода |
| `drv_power_extrap` | true | тяга выше 16 м/с — по постоянной мощности |
| `drv_table_file` | `maps/drive_map.csv` | характеристика `f(u, v)`; радиус колеса, редуктор и масса в ней уже учтены |
| `drv_monitor`, `drv_mon_win/on/off` | true, 3 с, 0.35 / 0.2 м/с² | монитор валидности модели |
| `drv_outage_s` | 0.5 с | тележки молчат дольше — счисление по модели |

### Фильтр скорости и проскальзывание (`estimator.yaml`)

| Параметр | Значение | Смысл |
|---|---|---|
| `kf_drive_model` | true | прогноз по модели привода (false — только кинематика) |
| `kf_r` | 0.03 м/с | шум тележки |
| `kf_q_jerk`, `kf_tau_a` | 1.0 м²/с⁵, 1.5 с | шум рывка, время корреляции ускорения (кинематика) |
| `kf_gate_sigma`, `kf_gate_min` | 5σ, 0.5 м/с | гейт невязки |
| `kf_dead_other`, `kf_zero` | 1.0, 0.05 м/с | «мёртвая» тележка |
| `kf_disagree_abs`, `kf_disagree_rel` | 0.5 м/с, 5 % | допуск расхождения тележек |
| `kf_v_max` | 25 м/с | предел скорости образца |
| `kf_slip_low`, `kf_slip_high` | 2 %, 5 % | пороги статуса проскальзывания |
| `kf_zupt`, `kf_resync_s`, `kf_max_horizon` | true, 1 с, 0.3 с | ZUPT, ресинхронизация, предел прогноза |
| `output.velocity_delay_s` | 0.08 с | задержка публикуемой скорости (`output.yaml`) |
