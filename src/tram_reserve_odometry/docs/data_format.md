# Формат данных и контракт жюри

## Датасет

122 rosbag2 (sqlite3, CDR), по одному каталогу на прогон: `<vehicle>_<hash>/<...>_0.db3` + `metadata.yaml`. Префикс `30618_` или `30639_` — номер трамвая. Всего ≈ 36.7 ч. В каждом bag одни и те же 7 топиков, но в 36 прогонах GNSS-сообщений нет вообще. Среди прогонов есть точные дубликаты (~25 пар).

## Входы (разрешены в основном контуре)

| Топик | Тип | Единицы и частота |
|---|---|---|
| `/vehicle/front_bogie_velocity` | `tram_vehicle_msgs/VelocitySensor` | **км/ч**, ~10 Гц |
| `/vehicle/rear_bogie_velocity` | `tram_vehicle_msgs/VelocitySensor` | **км/ч**, ~10 Гц |
| `/vehicle/driver_position_cmd` | `tram_vehicle_msgs/DriverControllerCommand` | int8: 0 — нейтраль, +1…+15 — тяга, −1…−15 — тормоз; 20 Гц |

```
# VelocitySensor.msg                # DriverControllerCommand.msg
std_msgs/Header header              std_msgs/Header header
float64 velocity                    int8 position
```

Организаторы подтвердили, что скорость тележек — в км/ч. Пакет переводит её в м/с (`input.bogie_velocity_unit: kmh`).

## GNSS — выставка и коррекция

| Топик | Тип | Смысл |
|---|---|---|
| `/sensing/gnss/{master,rover}/fix` | `sensor_msgs/NavSatFix` | lat/lon/alt антенны, 10 Гц, status 2 = RTK/GBAS |
| `/sensing/gnss/{master,rover}/vel` | `geometry_msgs/TwistStamped` | скорость антенны, **м/с** |

В проверочных прогонах GNSS гарантирован лишь в первые несколько секунд,
может появляться посреди прогона и может отсутствовать. Организаторы
подтвердили, что GNSS допустим для начальной выставки и для коррекции
положения после неё. Нода берёт фиксы обеих антенн для выставки
(см. [`coordinates.md`](coordinates.md)); после выставки подписки остаются,
и RTK-фикс(ы) корректно телепортируют продольную координату
(`map.gnss_correction`, `gnss_corr_require_pair: false` — одиночная антенна).

## Эталон судьи

По ответам организаторов:

- эталон — это их топик `/localization/kinematic_state`: GNSS, слитый с лидарной одометрией, высокоточный и без выбросов;
- в выданных bag этого топика **нет**;
- координаты — **MGRS**;
- точка — **base_link**: ось поворота передней тележки на уровне головки рельса;
- сравнение покомпонентно (x, y, z) и по 3D-расстоянию;
- отдельной эталонной скорости нет.

Для самопроверки эталон приближённо восстанавливается из двух антенн bag
(`live_map_core.GtTracker`, формулы — в [`coordinates.md`](coordinates.md)).

## Выходы (контракт жюри)

| Топик | Тип | Значение |
|---|---|---|
| `/result/velocity` | `tram_vehicle_msgs/VelocitySensor` | продольная скорость, **м/с**, в `velocity` |
| `/result/position` | `nav_msgs/Odometry` | положение base_link в `pose.pose.position`: MGRS x, y (м) и высота WGS84 z |

Требования:

- имена и типы топиков — ровно как в таблице;
- **`header.stamp` = время входа из bag**: судья сопоставляет с эталоном по ближайшей метке с допуском ~0.05 с. `frame_id` заполнен (`map`);
- только онлайн-публикация во время проигрывания; задержка «вход → результат» ≤ 100 мс, частота ≥ 10 Гц;
- QoS любой: судья подписывается с best-effort;
- GNSS-топики не публиковать.

Как нода соблюдает контракт:

- **Частота.** Цикл идёт на 20 Гц реального времени, публикуется каждая новая метка входов.
- **Задержка.** p95 — 8–25 мс на прогонах датасета.
- **Позиция до выставки.** `/result/position` не публикуется, пока позиция не определена; это меньше секунды при наличии GNSS.
