# Математическая модель

Модель состоит из двух связанных частей:

- **скорость** — фильтр Калмана с моделью тягового привода и продольной динамики вагона
  (`KalmanWheelEstimator` + `TableTractionModel`);
- **положение** — интегрирование скорости вдоль 1D-карты маршрута со сбросом ошибки
  на остановках и коррекцией по GNSS, когда он есть (`StopResetRouteIntegrator`).

Связь паспорта вагона с коэффициентами модели и сверка с данными — в
[`physical_model.md`](physical_model.md); устройство цикла ноды — в
[`architecture.md`](architecture.md).

## 1. Входы и выходы

| | Величина | Источник | Частота |
|---|---|---|---|
| вход | `z_f`, `z_r` — скорость передней и задней тележки, км/ч → м/с | `/vehicle/{front,rear}_bogie_velocity` | ~10 Гц |
| вход | `u` — позиция ручки контроллера −15…+15 | `/vehicle/driver_position_cmd` | 20 Гц |
| вход | фиксы антенн master и rover (выставка, коррекция) | `/sensing/gnss/{master,rover}/fix` | 10 Гц, не всегда |
| вход | карта: `s → (x, y, z, курс, уклон i(s), кривизна κ(s))`, остановки | `maps/` | — |
| выход | `v` — продольная скорость кузова, м/с | `/result/velocity` | 20 Гц |
| выход | положение base_link в MGRS (x, y, z) | `/result/position` | 20 Гц |

## 2. Продольная динамика и переход «сила/момент → скорость»

Трамвай — жёсткое тело на рельсах. Уравнение движения:

```
m·(1+γ)·dv/dt = F_т(u, v) − F_б(u, v) − W₀ − W_аэро(v) − W_к(R) − m·g·i(s)
```

В удельной форме (деление на приведённую массу `m_eq = m·(1+γ)`):

```
u_d(t)  = u(t − τ)                                                     запаздывание привода
a_мод   = θ_T·f⁺(u_d, v) + θ_B·f⁻(u_d, v) − w(v, s)·tanh(v/0.2) − k_g·g·i(s)·dir + b
w(v, s) = w₀ + c_aero·v² + k_curve·min(|κ(s)|, 1/R_min)                основное + аэродинамика + кривые
da/dt   = (a_мод − a)/T + w_j                                           инерция привода T
dv/dt   = a
```

- `f(u, v)` — **характеристика привода**: удельная сила на ободе колеса, м/с², по позиции
  ручки и скорости (`maps/drive_map.csv`, `f⁺` — тяга, `f⁻` — торможение). Это и есть
  переход от момента к скорости: момент двигателя `M` через редуктор `i_р` и колесо `r`
  даёт силу на ободе `F = N·η·i_р·M/r`, а `f = F/m_eq`. Таблица идентифицирована по
  данным датасета (ускорение — по тележкам, уклон — по карте) и сверена с паспортом:
  на +15 выше 8–10 м/с `a·v` ≈ const — зона постоянной мощности 4 × 72 кВт
  ([`physical_model.md`](physical_model.md), п. 3.1–3.2). Выше последнего узла таблицы
  (16 м/с) тяга продолжается по закону постоянной мощности `f·v = const`.
- `θ_T`, `θ_B` — адаптивные множители тяги и торможения, `θ = m_eq,ref/m_eq`:
  поглощают неизвестную загрузку (±18 % по паспорту). Масса меняется скачком на
  остановках, а в фильтре `θ` — медленное случайное блуждание (`drv_q_theta` = 10⁻³ 1/√с):
  скачок массы отслеживается с задержкой, по мере накопления измерений в тяге и торможении.
  Границы 0.8…1.25 — из паспорта (тара 24.6 т … полная 35.1 т) при опорной массе таблицы
  `m_eq,ref` ≈ 28–30 т; сама опорная масса — оценка (п. 3.1 [`physical_model.md`](physical_model.md)).
  При выбеге (`f` = 0) `θ` не наблюдаем; `θ` и `b` входят в ускорение аддитивно и
  разделяются только за счёт разных режимов движения.
- `b` — медленное возмущение (ветер, износ, неучтённое сопротивление).
- `tanh(v/0.2)` — сопротивление направлено против движения и гаснет на стоянке;
  при `v < v_hold` торможение не тянет вагон назад.
- Запаздывание `τ` = 0.225 с и инерция `T` = 0.138 с привода — идентификация по датасету,
  одни для тяги и торможения. Инерция `T` наложена на суммарное ускорение (включая
  сопротивление и уклон) — упрощение, см. [`physical_model.md`](physical_model.md), п. 1.
- `f(u, v)` — статическая функция ручки и скорости. Режимы контроллера, в которых ручка не
  задаёт силу (регулятор скорости на позиции −8, автоведение), в неё не входят — их ловит
  монитор валидности (п. 3); ограничения — в [`parameters.md`](parameters.md).

Прогноз между измерениями — точное решение на подшаге `drv_substep` (0.02 с) при
постоянном `a_мод`: ручка за шаг может смениться.

## 3. Оценка скорости и ускорения (фильтр Калмана)

**Состояние:** `x = [v, a, θ_T, θ_B, b]`. Ускорение `a` — компонента состояния: оно
оценивается фильтром совместно со скоростью, а не дифференцированием измерений.

**Режимы прогноза:**

- **модель** — уравнения п. 2 (ручка → привод → ускорение → скорость);
- **кинематика** (fallback) — модель Зингера `da/dt = −a/τ_a + w_j`, `θ` и `b` заморожены.

**Монитор валидности модели.** Ускорение по тележкам (МНК за 0.5 с) сравнивается с
`a_мод`, пропущенным через ту же инерцию `T`. RMS невязки за окно `drv_mon_win` больше
`drv_mon_on` — модель не объясняет движение (например, автоведение: ручка не отражает
тягу), фильтр переходит в кинематику. Обратно — когда RMS невязки без среднего меньше
`drv_mon_off`: постоянное смещение уходит в возмущение `b`.

**Модель измерений:** `z_i = v(t_i) + n_i`, `n_i ~ N(0, r²)`, `i` — передняя/задняя
тележка, `t_i` — метка образца. Каждый образец обрабатывается на своей метке
(predict до `t_i` → update).

**Робастность** — обе тележки стоят под одним жёстким кузовом:

1. «мёртвая» тележка: показывает ~0, когда другая едет быстрее `kf_dead_other`;
2. тележки расходятся сильнее `kf_disagree_abs + kf_disagree_rel·v` — отбрасывается та,
   что дальше от прогноза;
3. гейт по невязке `|ν| > max(kf_gate_sigma·√S, kf_gate_min)` — за шаг кузов так
   разогнаться не может;
4. образец быстрее `kf_v_max` (75 км/ч + запас) — не скорость кузова;
5. нет принятых измерений дольше `kf_resync_s` — ресинхронизация по тележкам;
6. ZUPT: все исправные тележки показывают 0 — `v = 0`, `a = 0`.

**Проскальзывание.** Статус (`/debug/slip`) — по относительному скольжению тележек
`(z_i − v)/max(v, 1 м/с)`: LOW > `kf_slip_low` (2 %, крип сухого рельса), MEDIUM >
`kf_slip_high` (5 %), HIGH — тележка отброшена правилами 2–3 за последнюю секунду.
Масштаб колеса `ε` в модели измерений не оценивается (`z_i = v + n_i`), поэтому постоянная
разница износа бандажей тележек (до 6.5 %) тоже попадает в «скольжение».

**Выход скорости.** Прогноз состояния на метку публикации (свежее образца тележек).
Эталон судьи запаздывает относительно тележек на ~0.06–0.10 с, поэтому в
`/result/velocity` идёт оценка на `метка − output.velocity_delay_s` (0.08 с) из истории;
положение считается по незадержанной скорости.

**Отказ тележек.** Тележки молчат дольше `drv_outage_s` — счисление по модели привода
от ручки.

## 4. Положение

**Выставка (первые секунды, GNSS).** Два фикса master и rover с близкими метками дают
ось вагона `û`; base_link = антенна − x_антенны·`û` (TF организаторов). base_link
проецируется на карту → маршрут, начальная координата `s₀` и направление `dir`.

**Интегрирование** по циклам публикации (20 Гц):

```
s ← s + dir·v·Δt   (mod L на кольце)
(x, y, z, курс) = карта(s)
```

**Неопределённость пути** между привязками растёт с пройденным путём `d`:

```
σ²(d) = σ_ref² + (drift_rel·d)² + drift_q²·d
```

(систематическая часть — масштаб колёс, случайная — проскальзывания).

**Сброс на остановках.** Вагон стоит (`|v| < stop_v_still` дольше `stop_t_still`), а
ближайшая остановка из `maps/stops.yaml` лежит в окне
`|s_ост − s| ≤ clamp(stop_gate_k·√S, stop_gate_min, stop_gate_max)`, `S = σ² + σ_ост²`:

```
s ← s + K·(s_ост − s),   K = σ²/S,   σ_ref² = (1 − K)·σ²,   d = 0
```

**Коррекция по GNSS** (когда фиксы появляются посреди прогона): RTK-фикс антенны →
проекция на путь → base_link → `s ← s_fix`, `σ_ref = gnss_corr_sigma_m`. Фикс
принимается только если он согласован: не дальше `gnss_corr_max_cross_m` от пути,
в окне `3σ` накопленной ошибки, серия фиксов за окно даёт одну и ту же поправку.
Это перенос в точку фикса с фиксированной неопределённостью, а не шаг фильтра с моделью
шума фикса: согласованное ложное RTK-решение проверки проходит.

**Привязка к остановке — одна гипотеза.** Если невязка у остановки больше окна, сброса нет;
если ошибка пути дальше растёт быстрее окна, привязка теряется до следующей GNSS-коррекции.

**Вывод.** Координаты карты (ENU) → UTM 37N → MGRS: `x = E − 300000`, `y = N − 6100000`,
`z` — высота WGS84 головки рельса ([`coordinates.md`](coordinates.md)).
